When uploading images or infographics to blog articles on asasmakeen.com, the CMS introduces 4 distinct problems: automatic quality/dimension reduction, an unwanted logo overlay, no inline placement within article body, and no image metadata fields (alt text, title, URL). These issues block the SEO team from adding visual content to articles and directly impact search performance.

🔍 The 4 Issues in Detail

1 Image Quality & Dimensions

What happens: Images uploaded at full resolution (e.g., 1920px wide, high-quality PNG) are automatically resized to smaller dimensions and compressed to low resolution.

Expected: The CMS should preserve the original image dimensions and quality, or at minimum provide the option to serve the full-resolution version.

Impact: Infographics with small text become unreadable. Professional images look pixelated and blurry.

2 Random Logo Overlay

What happens: The system automatically adds a logo/watermark on uploaded images. The placement appears random and inconsistent.

Expected: No automatic logo overlay. If branding is needed, it should be a toggle that the editor can enable/disable per image.

Impact: Ruins the visual quality of custom-designed infographics and branded content that already includes proper branding.

3 No Inline Image Placement

What happens: Images can only appear in a gallery at the bottom of the article. There is no way to insert images inline within the article body between paragraphs or sections.

Expected: The editor should allow inserting images at any point within the article content, between any two paragraphs or sections.

Impact: Infographics lose all context when separated from the relevant text. Users must scroll to the bottom to see visuals that should appear alongside the content they illustrate.

4 No Image Metadata Fields

What happens: There is no way to manually set alt text, title attributes, or link URLs on uploaded images.

Expected: Each image should have editable fields for: alt text (required for SEO & accessibility), title attribute, and an optional link URL (click-through).

Impact: Google Image Search cannot index images properly. Accessibility standards (WCAG) are not met. No ability to link images to relevant pages.

🛠 What Needs to Be Done

1
Fix image processing pipeline

Identify where uploaded images are being resized and compressed. Either remove auto-compression entirely or add a "preserve original quality" option. At minimum, the system should not downscale images below their uploaded dimensions.

2
Remove or make the auto-logo optional

Find the code that overlays a logo/watermark on uploaded images. Either remove it entirely or add a per-image toggle (default: OFF) so the editor can choose whether to apply it.

3
Enable inline image insertion in the blog editor

The blog article editor should support placing images within the article body HTML, not just in a separate gallery. This likely requires adding an "Insert Image" button to the rich text editor toolbar that generates an <img> tag at the cursor position within the article content.

4
Add image metadata fields

For each image (both gallery and inline), provide editable fields for: alt text (critical for SEO and accessibility), title attribute, and optional click-through URL. These should be rendered as proper HTML attributes on the <img> tag.

⚠️
Priority note: Issue #3 (inline placement) and Issue #4 (metadata) are the most critical for SEO. Even if image quality and logo issues take longer to resolve, enabling inline images with alt text would immediately unlock significant SEO value for all blog articles.

💻 Expected HTML Output

When an image is inserted inline in an article, the CMS should generate clean HTML like this:

💡
Example output for an inline infographic:

<img src="/uploads/original/infographic-housing-support.png" alt="شروط الدعم السكني 2026 - إنفوجرافيك" title="شروط الاستحقاق الأساسية بعد قرار 850" style="max-width:100%; height:auto;" />

Key requirements: src points to the original (not resized) file, alt and title are manually set by the editor, and the image renders inline within the article flow.

✅ Acceptance Criteria

  • Uploaded images maintain their original resolution and quality.
    Upload a 1920x1080 PNG and verify the served image matches the original dimensions and has no visible compression artifacts.
  • No automatic logo/watermark is added to uploaded images (or there is a toggle to disable it).
    Upload an image and verify no overlay is added. If a toggle exists, it should default to OFF.
  • Images can be placed inline within the article body at any position.
    Insert an image between two paragraphs in the editor and verify it renders at that position on the live page, not in a separate gallery.
  • Each image has editable fields for alt text, title, and link URL.
    Set custom alt text on an image, publish, and inspect the HTML source to confirm the alt attribute contains the exact text entered.
  • Existing images and articles are not affected by the changes.
    Verify that currently published articles with gallery images still render correctly after the update.
