🔍 Complete List of Issues (17 Total)

The audit identified 17 distinct issues across the current sitemap. They are grouped by severity: 5 Critical, 6 High, 3 Medium, and 3 Low.

Critical Issues (5)

These are blocking Google from properly crawling and indexing the site.

Critical C1. Sitemap is static, not CMS-generated

The XML comment at the top of the sitemap reads: "created with Free Online Sitemap Generator www.xml-sitemaps.com". The sitemap was generated once in April 2025 and saved as a static file. It is not connected to the CMS in any way.

Impact: Any page created after April 2025 is automatically excluded. The sitemap will always be out of date.

Fix: Replace with a dynamic sitemap generator (sidecar script) that auto-updates when content changes.

Critical C2. Massive coverage gap

The sitemap has 500 URLs. The site has thousands of indexable pages. The table above shows real examples of top-performing pages that are completely missing. Anything published after the sitemap generation date in April 2025, and many older pages as well, are not included.

Impact: Google may not discover or prioritize high-value content. The #1 traffic page (blog 166) is entirely absent.

Fix: Dynamic generation that queries the CMS database and includes every canonical, indexable page.

Critical C3. All <lastmod> dates are fake and identical

Every single HTML page in the sitemap has the same <lastmod> timestamp: 2025-04-21T08:22:00+00:00. This is the date the sitemap was generated, not when pages were actually modified.

Per Google's own documentation, Google only trusts <lastmod> when it is "consistently and verifiably accurate." When Google detects fake dates, it ignores the field entirely.

Impact: Google cannot use the sitemap to prioritize re-crawling recently updated content.

Fix: Each URL's <lastmod> must reflect its real last modification date from the CMS database (updated_at field).

Critical C4. No hreflang annotations

The site serves content in Arabic and English, but the sitemap has zero xhtml:link hreflang annotations. This is the most scalable way to tell Google which Arabic page pairs with which English page, especially for a bilingual site of this size.

Impact: Google may show the wrong language version in search results for each market. Saudi users might see the English version, and English users the Arabic one.

Fix: Add xhtml:link rel="alternate" hreflang="ar" and hreflang="en" for every page that has a language counterpart. Requires adding the xmlns:xhtml namespace to the <urlset> element.

Critical C5. Non-canonical URLs still in the sitemap

The current sitemap includes URLs that were identified as non-canonical in previous tickets. Tickets #001 (Duplicate URLs) and #003 (Hreflang Tags) already defined which URL version is canonical for each page, and the fixes have been applied (redirects and canonical tags are in place). However, the sitemap was never updated to reflect those changes, so it still lists the non-canonical versions.

A sitemap should only contain canonical URLs. If a URL has been resolved as non-canonical in a previous ticket, it should not appear in the sitemap.

Fix: The new dynamic sitemap generator should only include the canonical version of each URL. The simplest way: for every URL the script generates, check that it matches the page's <link rel="canonical"> tag. If it does not match, do not include it.

Fix: Same rule as C5: only include the canonical version of each URL. The sidecar script should check against the page's <link rel="canonical"> tag.

The same listing page appears under multiple URL patterns. For example, "Our Projects" appears as /en/u/3/our-projects, /en/u/3/projects, and /en/u/3/مشاريعنا. The "Available for Sale" listing appears under 7+ different URLs across both languages.

High H5. No root URL in the sitemap

The sitemap starts with https://asasmakeen.com/en but does not include the root domain https://asasmakeen.com/. The canonical entry point of the site is not declared.

Fix: Include the root URL if it serves content, or ensure only its redirect target is included.

High H6. No image sitemap tags

The sitemap does not use the image:image extension. For a real estate company with visual content (project photos, floor plans, maps), this is a missed opportunity. Google Image Search is a significant traffic source for real estate.

Fix: Add image:image elements for project and blog pages with image:loc, image:title, and image:caption in both Arabic and English.

Medium Issues (3)

Medium M1. camelCase URL segments

Multiple URLs use camelCase: /availableForSale, /underConstruction, /availableForRent. URLs are case-sensitive per HTTP spec, creating potential duplicate content.

Fix: Standardize to lowercase with hyphens (e.g., available-for-sale). Add 301 redirects from old versions.

Medium M3. <priority> values are auto-generated

The priority tiers (1.00, 0.80, 0.64, 0.51, 0.41) are based on URL depth, not business value. The housing support blog with ~756 visits/month would get the same priority as a low-traffic news item.

Note: Google officially ignores <priority> (confirmed by John Mueller). It can still be used as an internal signal but has no SEO impact.

Medium M4. Missing <changefreq>

No URLs include a <changefreq> tag. Google ignores this field entirely, but Bing and other search engines may still use it as a hint.

Fix: Optional. Can add weekly for blogs/news, monthly for projects, yearly for static pages. Low priority since Google ignores it.

Low Issues (3)

Low L1. Flat sitemap, no sitemap index

The sitemap is a single <urlset> file. With the site's page count, it should be organized as a <sitemapindex> with child sitemaps by content type (pages, projects, blogs, news) and language.

Fix: Implement sitemap index structure (see ideal structure below).

Low L2. robots.txt blocks SEO tool crawlers

robots.txt blocks AhrefsBot, SemrushBot, and others. This limits ongoing SEO monitoring. Not a sitemap issue per se, but relevant context.

Low L3. Crawl-delay directive for Googlebot

robots.txt sets Crawl-delay: 1 for Googlebot. Google ignores this directive entirely (they recommend using Search Console settings). For Bing, a 1-second delay may slow indexing.

Fix: Remove Crawl-delay for Googlebot. Consider removing for Bingbot as well.

🏗 What the New Sitemap Should Look Like

File Structure

Rules for What Goes In

🛠 How to Build It: The Sidecar Approach

💡
Why "sidecar"? Since the website runs on a custom JavaScript CMS, modifying the core to generate sitemaps could be risky and time-consuming. Instead, we recommend a standalone Node.js script that runs alongside the CMS. It reads from the same database, generates the sitemap files, and writes them to the web server's public directory. No changes to the CMS code needed.
1
Create a standalone Node.js script

A single file (e.g., generate-sitemap.js) that connects to the same database the CMS uses. It reads all content tables (pages, blogs, news, projects) and builds the sitemap XML files.

2
Query the database for all indexable content

For each content type, pull: ID, Arabic slug, English slug, updated_at timestamp, status (published/draft), and featured image URL. Only include published, indexable pages.

3
Build canonical URLs only

For each page, construct only the canonical URL as defined by the site's existing canonical tags and the rules established in Tickets #001 and #003. Skip any URL that would be non-canonical.

4
Generate XML with proper namespaces

Include xmlns:xhtml for hreflang and xmlns:image for image tags. Generate the sitemap index file pointing to each child sitemap.

5
Write files to the web server's public directory

Output sitemap.xml (index) and child sitemaps to the same directory the web server serves. This replaces the old static file.

6
Schedule with cron (every 6 hours)

Set up a cron job to run the script regularly: 0 */6 * * * node /path/to/generate-sitemap.js. This ensures the sitemap stays fresh without any CMS modifications.

7
Ensure trailing slashes are consistent across all URLs

Every URL in the sitemap must have a consistent trailing slash policy. If the site uses trailing slashes (e.g., https://asasmakeen.com/ar/), then every URL in the sitemap must also include the trailing slash. A URL with and without a trailing slash are technically two different URLs, and inconsistency can cause duplicate content issues.

Pseudocode: The Core Logic

📄 generate-sitemap.js - simplified logic 
// 1. Connect to database
const db = connectToDatabase(process.env.DB_URL)

// 2. Query all published content
const blogs   = db.query("SELECT id, slug_ar, slug_en, updated_at, image FROM blogs WHERE status = 'published'")
const projects = db.query("SELECT id, slug_ar, slug_en, updated_at, image FROM projects WHERE status = 'published'")
const news    = db.query("SELECT id, slug_ar, slug_en, updated_at, image FROM news WHERE status = 'published'")

// 3. For each item, build a URL entry with hreflang
function buildEntry(item, type) {
  const arUrl = `https://asasmakeen.com/ar/${type}/d/${item.id}/${item.slug_ar}`
  const enUrl = `https://asasmakeen.com/en/${type}/d/${item.id}/${item.slug_en}`

  return {
    loc: arUrl,  // or enUrl for the EN sitemap
    lastmod: item.updated_at.toISOString(),
    hreflang: [
      { lang: "ar", href: arUrl },
      { lang: "en", href: enUrl }
    ],
    images: item.image ? [{ loc: item.image }] : []
  }
}

// 4. Generate XML files
writeXML("sitemap-blogs-ar.xml",  blogs.map(b => buildEntry(b, "blogs")))
writeXML("sitemap-blogs-en.xml",  blogs.map(b => buildEntry(b, "blogs")))
// ... repeat for projects, news, pages

// 5. Generate sitemap index
writeSitemapIndex("sitemap.xml", [
  "sitemap-pages.xml",
  "sitemap-blogs-ar.xml", "sitemap-blogs-en.xml",
  "sitemap-projects-ar.xml", "sitemap-projects-en.xml",
  "sitemap-news-ar.xml", "sitemap-news-en.xml"
])

// 6. Log result
console.log(`Sitemap generated: ${totalUrls} URLs across ${childSitemaps} files`)
⚠️
Alternative approach: If the team prefers, they can add an API route (e.g., /api/sitemap) to the CMS instead of a sidecar script. The route would dynamically generate the sitemap on each request. The sidecar approach is recommended because it has zero risk to the existing CMS and can be deployed/debugged independently.

    Pick any bilingual page. It should appear in both the AR and EN sitemaps, each with hreflang links to both versions.

    All 500+ URLs should NOT have the same date. Dates should reflect actual content update times from the database.

    Every URL must either all have a trailing slash or all not have one. Inconsistency means Google treats them as different URLs, causing duplicate content.
  • The sitemap auto-regenerates (cron job runs every 6 hours).
    Publish a new blog post or edit an existing one, wait for the next cron cycle, and verify the sitemap reflects the change.
  • Sitemap is submitted to Google Search Console and Bing Webmaster Tools.
