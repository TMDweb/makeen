Makeen's website has full Arabic and English versions, but not a single page includes hreflang tags. Hreflang is the standard way to tell Google "this Arabic page has an English equivalent here, and vice versa." Without it, Google treats both versions as separate, unrelated pages competing with each other. This means the site is losing ranking power on both languages and users may be served the wrong language version in search results.

🔍 What Is Hreflang and Why Does It Matter

The Problem: Google Doesn't Know AR and EN Pages Are Related

Right now, when Google crawls asasmakeen.com/ar/about and asasmakeen.com/en/about, it sees two separate pages with no connection between them. It has to guess:

  • Are these duplicates? Should I only index one of them?
  • Which one should I show to Arabic-speaking users? Which for English?
  • Are they competing with each other for the same keywords?

Hreflang tags answer all of these questions. They tell Google: "This Arabic page and this English page are language versions of the same content. Show the Arabic one to Arabic users and the English one to English users."

What Happens Without Hreflang (Current Situation)
  • Wrong language in search results - A user in Riyadh searching in Arabic might see the English version of a property page, and vice versa
  • Duplicate content signals - Google may treat the AR and EN versions as duplicates and only index one, ignoring the other
  • Split ranking power - Backlinks and ranking signals pointing to the Arabic page don't help the English page, and vice versa. With hreflang, Google consolidates this value
  • Poor user experience from search - Users click a search result and land on a page in a language they can't read

Every page that has a version in another language must declare that relationship using hreflang tags.

For a bilingual AR/EN site like Makeen, every page needs 3 hreflang link tags: one for Arabic, one for English, and one x-default.

🧩 What Each Page Needs

Every page on the site needs three things added to its <head> section:

1. The html lang attribute

The <html> tag itself must declare the page language.

Current (no lang)
<html>

Correct
<html lang="ar" dir="rtl">
Arabic pages get lang="ar" dir="rtl"
English pages get lang="en" dir="ltr"

2. Three hreflang link tags in the <head>

These tell search engines how the Arabic and English versions of each page are connected.

📄 Example: Homepage /ar 
<!-- On the Arabic homepage (asasmakeen.com/ar) -->
<link rel="alternate" hreflang="ar"        href="https://asasmakeen.com/ar" />
<link rel="alternate" hreflang="en"        href="https://asasmakeen.com/en" />
<link rel="alternate" hreflang="x-default" href="https://asasmakeen.com/ar" />
📄 Example: Homepage /en 
<!-- On the English homepage (asasmakeen.com/en) -->
<link rel="alternate" hreflang="ar"        href="https://asasmakeen.com/ar" />
<link rel="alternate" hreflang="en"        href="https://asasmakeen.com/en" />
<link rel="alternate" hreflang="x-default" href="https://asasmakeen.com/ar" />

Key point: Both the Arabic AND the English page must contain the same set of 3 tags. The tags are identical on both versions. This is how Google confirms the relationship is real (each page vouches for the other).

3. The x-default tag explained

The x-default tag tells Google: "If the user's language doesn't match Arabic or English, send them here." For Makeen, this should point to the Arabic version since the primary audience is in Saudi Arabia.

⚠️ Common Mistakes to Avoid

Mistake 1: Adding hreflang only on one version

If the Arabic page has hreflang tags pointing to the English page, but the English page does NOT have hreflang tags pointing back to the Arabic page, Google will ignore both. The tags must be reciprocal (present on both sides).

Mistake 2: Using wrong language codes

The language codes must follow the ISO 639-1 standard. For Makeen:

Wrong
hreflang="arabic"
hreflang="ara"
hreflang="AR"
Correct
hreflang="ar"
hreflang="en"
hreflang="x-default"
Mistake 3: Using relative URLs instead of absolute URLs
Wrong
href="/ar/about"
Relative URL - Google requires full URLs
Correct
href="https://asasmakeen.com/ar/about"
Absolute URL with https://
Mistake 4: Not including a self-referencing tag

Each page must include a hreflang tag pointing to itself, not just to the other language. So the Arabic page must have both hreflang="ar" (pointing to itself) AND hreflang="en" (pointing to the English version).

🛠 What Needs to Be Done

1
Add the lang attribute to the <html> tag

Arabic pages: <html lang="ar" dir="rtl">
English pages: <html lang="en" dir="ltr">
This is a one-line change in the base layout template.

2
Build the hreflang URL for the alternate language version

For any page being rendered, you already know its URL. To build the alternate URL, swap the language prefix (/ar/ to /en/ or vice versa) and use the correct slug for that language. The slugs are already stored in the database (one Arabic, one English per page).

3
Inject the 3 hreflang link tags into the <head>

In the base layout template (the one every page extends), add logic to output the 3 link tags. This should work dynamically for all page types: properties, blogs, static pages.

4
Handle edge cases

Some pages may not have a translated version. If a page exists only in Arabic (no English equivalent), it should still have hreflang="ar" and x-default tags pointing to itself, but no hreflang="en" tag.

Logic Reference

📄 Pseudocode - Generating hreflang tags 
// In the base layout template, inside <head>:

currentLang  = request.language          // "ar" or "en"
currentURL   = request.fullCanonicalURL    // absolute URL of this page
alternateLang = (currentLang == "ar") ? "en" : "ar"

// Build the alternate URL
// For dynamic pages (property, blog): swap prefix + use correct slug
if page.hasTranslation(alternateLang):
    alternateURL = buildURL(alternateLang, page.slugFor(alternateLang))
else:
    alternateURL = null  // no translation exists

// Output the tags
output: <link rel="alternate" hreflang="{currentLang}" href="{currentURL}" />

if alternateURL:
    output: <link rel="alternate" hreflang="{alternateLang}" href="{alternateURL}" />

// x-default always points to the Arabic version (primary market)
defaultURL = (currentLang == "ar") ? currentURL : alternateURL
output: <link rel="alternate" hreflang="x-default" href="{defaultURL}" />

Important note about Ticket #001: Once the duplicate URL fix from Ticket #001 is deployed (so each page only has 2 URLs instead of 4), the hreflang tags should point to the correct canonical URLs only. The Arabic hreflang must use the Arabic slug, and the English hreflang must use the English slug. Never point hreflang to a URL that redirects.

🔗 While You're at It: Add Canonical Tags Too

The site is also missing canonical tags on every page. Since you'll be editing the <head> section to add hreflang, this is the perfect time to add canonicals as well. It's one extra line per page.

📄 Add this alongside the hreflang tags 
<!-- Canonical tag: tells Google which URL is the "official" version -->
<link rel="canonical" href="https://asasmakeen.com/ar/about" />

<!-- Hreflang tags: language versions -->
<link rel="alternate" hreflang="ar"        href="https://asasmakeen.com/ar/about" />
<link rel="alternate" hreflang="en"        href="https://asasmakeen.com/en/about" />
<link rel="alternate" hreflang="x-default" href="https://asasmakeen.com/ar/about" />

The canonical tag should always point to the current page's own URL (the clean, correct version). It tells Google "this is the official URL for this content, ignore any other variations you may have found."

Why add canonical now? Canonicals and hreflang work together. Google recommends using both. The canonical tag handles duplicates within the same language (e.g., if a page is accessible with and without a trailing slash), while hreflang handles the cross-language relationship. Adding them together is more effective than adding them separately.

  • Every page has lang and dir attributes on the <html> tag
    Arabic pages: lang="ar" dir="rtl" | English pages: lang="en" dir="ltr"
  • Every page has 3 hreflang link tags in the <head>

  • The hreflang tags are identical on both the AR and EN version of each page
