Why the step-skip matters
If you block crawlers with Disallow: / before deploying the X-Robots-Tag: noindex header, Google's crawlers cannot reach the pages to see the noindex signal. URLs already in the index stay there indefinitely as orphaned results. For s, forms, and apps, the fix is to temporarily revert robots.txt to Disallow: (empty), deploy the X-Robots-Tag header, wait 2-4 weeks for Google to process the noindex, then switch back to Disallow: /.

Critical C5. Per-engine groups bypass every disallow rule for Google, Bing, and 4 other crawlers

📡
Live status: Not done. The main production file still contains the crawler-specific groups for Googlebot, Bingbot, Slurp, DuckDuckBot, Baiduspider, and YandexBot.

The current main robots.txt has separate User-agent: groups for Googlebot, Bingbot, Slurp, DuckDuckBot, Baiduspider, and YandexBot. Each one looks like this:

❌ Current (broken)
User-agent: Googlebot
Allow: /
Crawl-delay: 1

Per Google's spec, each crawler picks exactly one group — the one with the most specific user-agent name that matches it — and ignores every other group. So Googlebot reads its own block (just Allow: / and an ignored Crawl-delay) and completely ignores the User-agent: * block with all the disallows.

Impact: Googlebot, Bingbot, Slurp, DuckDuckBot, Baiduspider, and YandexBot are currently allowed to crawl every single path on the site — /admin/, /dashboard/, /login, /api/, /storage/, /.env, /composer.json, all of it. The defensive disallows in the * group only apply to crawlers that don't have their own group, which is essentially nobody important.

Fix: Delete every per-engine User-agent: block. Once they're gone, every crawler falls back to the User-agent: * group and inherits all the disallows. The recommended replacement file in Section 4.1 already does this.

✅ Fixed (one shared group)
User-agent: *
Disallow: /admin/
Disallow: /dashboard/
# ... etc. Googlebot, Bingbot, Yandex, etc. all inherit these.

📘 Google's Hard Rules for Robots.txt

RuleWhy it matters here
Must be UTF-8 encodedAny BOM or non-UTF-8 bytes will cause Google to skip lines.
Must be at the root: /robots.txtSubfolder files (e.g. /blog/robots.txt) are ignored.
File size must be under 500 KBAnything beyond 500 KB is truncated. Current main file is 3.1 KB, safe.
Valid only for the exact protocol + host + portWhy we need a separate file on every subdomain. See info box in the host evaluation section above.
One directive per line, paths are case-sensitive/Login and /login are two different rules.
Googlebot supports only: User-agent, Disallow, Allow, SitemapNoindex: in robots.txt has been unsupported since 2019. Crawl-delay is ignored by Google.
Wildcard User-agent: * does NOT include Google AdsBotIf we ever run Google Ads on these domains, AdsBot must be named explicitly to be blocked.
For 4xx responses (except 429), Google assumes "no restrictions"This is exactly what's happening on apps., forms., prt. — the SPA returns a 200 with HTML, which Google reads as "no robots.txt → crawl everything."
Disallow only blocks crawling, never indexingTo deindex, use X-Robots-Tag: noindex header. See M1.
In conflicts, Google uses the least restrictive ruleAn Allow: can override a broader Disallow: when you need a targeted exception inside a blocked directory.
