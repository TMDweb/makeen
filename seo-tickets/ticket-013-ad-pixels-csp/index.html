Ticket #013 - Allow Advertising Pixels Through the Website CSP

Project: asasmakeen.com
Priority: High
Date: July 12, 2026
Owner: Website / CDN developer

ملخص المهمة

وسوم الإعلانات الخاصة بـ Snapchat وMeta وX يتم تفعيلها من Google Tag Manager، لكنها تفشل بعد ذلك لأن سياسة أمان المحتوى Content Security Policy (CSP) في موقع مكين تسمح بنطاقات Google فقط تقريباً، وتمنع تحميل مكتبات منصات الإعلانات الأخرى أو إرسال طلبات القياس إليها.

المطلوب هو تحديث ترويسة CSP الحالية وإضافة النطاقات الرسمية اللازمة لكل منصة، مع الحفاظ على جميع القيم الموجودة. tr.snapchat.com نطاق رسمي تابع لـ Snapchat وليس نطاق دولة تركيا .tr. لا يوجد تعديل مطلوب على Triggers أو Pixel IDs داخل GTM.

Problem: GTM invokes the Makeen Snap, Meta and X page-view tags, but the browser blocks their external JavaScript or measurement endpoints under the site's current CSP.

Required fix: update the existing website/CDN CSP with the documented and runtime-verified hosts listed below. Clear the CDN cache, then verify all three platforms in GTM Preview and the browser network panel.

FailedSnap PageView
FailedMeta PageView
FailedX PageView

🔎 What Was Verified

1
GTM Preview connected successfully

Container GTM-PZC74T44 loaded on https://asasmakeen.com/ar/.

2
The triggers matched

The affected tags appear under Tags Fired, proving that All Pages is not the shared problem.

3
Three advertising tags failed

Tag Assistant reports the Snap, Meta and X page-view tags as failed while the Google tags fire successfully.

4
The website CSP excludes all three vendors

The final HTTP 200 response permits Google hosts but omits the loaders and measurement hosts required by Snap, Meta and X.

Evidence standard: X publishes explicit CSP guidance. Snap explicitly documents its loader; the request directives are also verified through the installed GTM template and current runtime. Meta does not publish a complete public CSP table, so its hosts are taken from Meta's current platform-owned fbevents.js. tr.snapchat.com is under snapchat.com; it is not the Turkish country-code domain .tr.

🚫 What Does Not Need to Change

  • Do not change the GTM page-view triggers.
    All Pages already matches; the shared failure occurs after invocation.
  • Do not replace the vendor IDs.
    The failure pattern is host-level, not an invalid-ID diagnosis.
  • Do not replace the tags with Custom HTML.
    Custom HTML would still load the same external vendor libraries and remain subject to CSP.
  • Do not treat this as a geography issue.
    These are vendor service hostnames used by the integrations, not country-specific routing choices.

🖥️ Where to Apply It

Update whichever layer currently emits the response header:

Possible ownerTypical location
Hosting / CDNSecurity headers, response-header rules, or edge configuration
Nginxadd_header Content-Security-Policy ... always;
ApacheHeader always set Content-Security-Policy "..." in server config or .htaccess
ApplicationSecurity middleware or framework response headers

Only one layer should own the effective policy. Check that the server and CDN are not emitting two conflicting CSP headers.

✅ Acceptance Criteria

  • The final 200 response includes all Snap, Meta and X additions under their specified CSP directives.
  • Website/CDN caches are cleared after deployment.
  • scevent.min.js, fbevents.js and uwt.js load successfully in Chrome.
  • window.snaptr, window.fbq and window.twq are defined after page load.
  • GTM Preview reports the Snap, Meta and X page-view tags as Fired, not Failed.
  • The Network panel shows successful vendor measurement requests to Snapchat, Meta and X endpoints.
  • Existing Google and other tracking tags are regression-tested after the CSP deployment.

🔁 Optional Server-Side Alternative

Snap, Meta and X each offer server-side conversion APIs. Those are separate implementations, not GTM web-tag toggles. They require platform credentials, backend event generation, attribution data, consent handling, verification and event deduplication.
