Summary Scale Root Cause URL List Fix Verify Priority

Every page on asasmakeen.com is reachable at two URLs: the canonical one (e.g. https://asasmakeen.com/ar) and a duplicate that contains /public/ in the path (https://www.asasmakeen.com/public/ar). Both return HTTP 200 with the same content, and the /public/ version's <link rel="canonical"> tag points to itself instead of the clean URL, so Google is told both versions are originals. Each page is therefore indexed twice: ranking signals and external link equity split between the duplicates instead of consolidating on the clean URL, and Laravel's internal directory name leaks into search results. 214 URLs are affected; the full list is in this Drive sheet. The fix is a single server-level 301 rule.

🔬 Root Cause & Live Verification

Laravel's document root is the public/ directory. When the web server (nginx or Apache) does not enforce that /public/... requests are blocked or redirected, every page becomes reachable via two URLs: the canonical one (without /public/) and the duplicate (with /public/). Both render successfully and both are indexable.

Live test (May 13, 2026)

🚨
The canonical tag on /public/ URLs points back to itself, not to the clean URL. So Google is being told both versions are "the original." Each /public/ page therefore competes with its clean twin for ranking, splits internal link equity, and inflates the indexable footprint of the site.
📘
Why this matters more than a normal duplicate: a single 301 at the server tier resolves all 214 URLs at once. There is no per-page work and no application code change required if the rewrite is added at nginx/Apache. The fix is intentionally low-effort and high-impact.

🛠 The Fix

Preferred — server-level 301 (one rule, covers everything)

nginx

📄 nginx server block
# Strip /public/ from the URL and 301 to the clean path.
# Place inside the server { } block, before the catch-all location.
location ~ ^/public/(.*)$ {
    return 301 https://asasmakeen.com/$1$is_args$args;
}

Apache (.htaccess)

📄 .htaccess at the docroot
RewriteEngine On
# 301 any request that begins with /public/ to the same path without it.
RewriteCond %{REQUEST_URI} ^/public/(.*)$
RewriteRule ^public/(.*)$ https://asasmakeen.com/$1 [R=301,L]
📘
Host normalization is bundled. Both rules redirect to the apex (https://asasmakeen.com), which collapses the www variants from the GSC list (www.asasmakeen.com/public/ar → asasmakeen.com/ar) into a single hop. The existing www → apex redirect documented in Ticket #006 already handles requests that arrive without /public/, so no double-redirect chain is created.

Acceptable fallback — application-level 301

If the dev team can't add a server-level rule, Laravel can handle it in middleware:

📄 app/Http/Middleware/StripPublicPrefix.php
public function handle($request, Closure $next)
{
    if (str_starts_with($request->getPathInfo(), '/public/')) {
        $clean = substr($request->getPathInfo(), 7); // drop "/public"
        return redirect('https://asasmakeen.com' . $clean, 301);
    }
    return $next($request);
}
⚠️
Why server-level is preferred: the application-level redirect still boots Laravel for every /public/ hit, which is wasted CPU on requests that exist only to be redirected away. nginx/Apache rewrites short-circuit before PHP runs.

Also fix the canonical tag on legacy URLs (defensive)

The 301 alone will deindex the /public/ URLs over the next few crawls. As a belt-and-suspenders, the SPA template currently emits <link rel="canonical" href=".../public/..."> when the request path includes /public/. Once the 301 is in place this code path is unreachable, but if the redirect is rolled out gradually, harden the template to always emit the canonical without the prefix:

📄 Blade template (or wherever canonical is rendered)
<link rel="canonical"
      href="{{ str_replace('/public/', '/', url()->current()) }}" />
