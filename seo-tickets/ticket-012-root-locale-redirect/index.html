Ticket #012 - Replace Root Locale Detection with a 301 to /ar

Project:asasmakeen.com
Priority:Medium
Date:June 10, 2026
Assignee:Abdo (dev, Makeen)

ملخص المهمة

الجذر asasmakeen.com/ يحوّل الزائر حالياً تحويل 302 إلى /ar أو /en حسب لغة المتصفح. Google تنصح صراحةً بعدم التحويل التلقائي حسب اللغة، و Googlebot يزحف بدون ترويسة لغة فيصل دائماً إلى /en، بينما وسوم hreflang تعلن أن النسخة الافتراضية هي /ar. النتيجة: إشارات متضاربة على أهم رابط في الموقع.

المطلوب: إلغاء كشف اللغة في الجذر واستبداله بتحويل 301 دائم ثابت إلى /ar لجميع الزوار. وسوم hreflang الحالية (x-default = /ar) تبقى كما هي بدون أي تعديل، وتبديل اللغة يبقى بيد المستخدم عبر زر اللغة في الموقع.

The root URL https://asasmakeen.com/ currently 302-redirects per visitor based on the Accept-Language header. Google's documentation explicitly advises against automatic language redirection, and Googlebot crawls without an Accept-Language header, so it always lands on /en - while the site's hreflang declares x-default = /ar. The site's most-linked URL is sending contradictory signals.

Fix: remove the language detection at the root and replace it with a single, unconditional, permanent 301 to /ar for every request. The existing hreflang markup stays exactly as it is. Language switching remains user-initiated via the site's AR/EN switcher.

🔎 Current Behavior (verified 2026-06-10)

Request to https://asasmakeen.com/ Response
Accept-Language: ar-SA,ar 302 → /ar
Accept-Language: en-US,en 302 → /en
No Accept-Language header (most bots, incl. Googlebot) 302 → /en

Both /ar and /en declare <link rel="alternate" hreflang="x-default" href="https://asasmakeen.com/ar">.

Three problems:

1. Against Google guidance. Auto language redirection is explicitly discouraged (references below), and since Googlebot sends no Accept-Language header, the crawler can never see the Arabic side of the redirect.

2. Contradictory signals. The markup declares /ar as the default version, but the server sends every header-less visitor and bot to /en.

3. Wasted link equity. Nearly all external backlinks point at the bare root. A temporary (302) redirect whose destination varies per visitor gives Google no stable canonical to consolidate that equity onto.

🛠️ The Fix

1. Root 301s to /ar, unconditionally

Delete the Accept-Language detection logic for /. Every request to the root - any visitor, any bot, any header - gets a permanent redirect:

🖥️ Target behavior
GET https://asasmakeen.com/
HTTP/2 301
location: https://asasmakeen.com/ar

Arabic is the default because it is the primary market, the primary content language, and already the declared x-default. The 301 (permanent) tells Google to consolidate the root's backlink equity onto /ar.

2. Hreflang stays unchanged

The current markup on /ar and /en (hreflang="ar" → /ar, hreflang="en" → /en, x-default → /ar) is already correct for this setup. Do not modify it. English users searching in English still reach /en through the hreflang="en" annotation in search results.

3. No auto-redirect anywhere else

Language switching is user-initiated only, via the visible AR/EN switcher. Do not reintroduce Accept-Language redirection on any URL.

📚 References

"Avoid automatically redirecting users from one language version of a site to a different language version of a site. For example, don't redirect based on what you think the user's language may be."

Google Search Central - Managing multi-regional and multilingual sites

Googlebot "sends HTTP requests without setting Accept-Language in the request header" and crawls primarily from US IPs. "We recommend using separate locale URL configurations and annotating them with rel="alternate" hreflang annotations."

Google Search Central - How Google crawls locale-adaptive pages

The x-default value "is recommended for specifying the fallback page for users whose language settings don't match any of your site's localized versions."

Google Search Central - Localized versions of your pages
